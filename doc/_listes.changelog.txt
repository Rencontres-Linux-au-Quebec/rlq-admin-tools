## 1.3.20261020.211944 — Personal configuration file ~/.PROGRAM.conf (not .cfg)

Reason:
  « La règle de fichier de config est de lire avant dans /etc/default/programme.conf et si un fichier existe dans ~/.programme.conf ... pas .cfg »
  « tous les programmes ainsi que la doc »

Changes:
  - LIEUX_UTILISATEUR = ~/.nginx-tools-ip-location.conf; chemins() goes through _personnel() (apps/_config.py migrer_ancien).
  - apps/_listes.sh: listes_fichiers_lieux reads ~/.nginx-tools-ip-location.conf through _listes_personnel (apps/_i18n.sh config_migrer_ancien; without it, the legacy file if alone).

Bugs fixed:
  none.

Safeguards and edge cases:
  - Legacy ~/.NAME.cfg alone: renamed to ~/.NAME.conf (same content, owner and permissions), one notice on stderr (French and English).
  - Both files present: ~/.NAME.conf is read, ~/.NAME.cfg is IGNORED and reported once per run — never merged nor deleted (its settings may differ).
  - Rename impossible (read-only home…): the legacy file is read as is, with a notice — settings never vanish silently.
  - NGINX_TOOLS_CONFIG_MIGRER=0: no rename. One notice per file and per run, even across child programs (NGINX_TOOLS_CONFIG_SIGNALES).

Checks:
  - New tests test_config_commune.AncienNomPersonnel (Python and bash: rename, both files, read-only home as non-root, English notice, common file);
  - test_conventions: no ~/.NAME.cfg in help, templates and documentation; full suite run-all.sh; ShellCheck 0.11.0 on the bash programs.

Action required:
  none — an existing ~/.PROGRAM.cfg is renamed ~/.PROGRAM.conf automatically at the next run. If both files exist, the program says so:
  move the settings of the .cfg into the .conf, then delete the .cfg.

## 1.0.20261007.093208 — Première version : liste blanche et lieux, lecteur commun

Motif de la demande :
  « Il faudrait sortir certains fichiers de configuration personnels reliés à mon setup des .ZIP puisque je veux mettre cela sur GITHUB. Par exemple la liste des
  IP définies dans apps/team-ips.list : dans /etc/default, avec le début de nom « nginx-tools » (nginx-tools-white-list.conf…), et un autre fichier
  nginx-tools-ip-location.conf pour indiquer le lieu d'une plage d'adresses (université : plusieurs personnes derrière la même adresse). » Décisions : tirets
  partout ; liste blanche lue seulement dans /etc/default ; profils gardés avec surcharge facultative (phase C) ; syntaxe « # Lieu [partagée] [protégée] ».

Détail des modifications :
  - apps/_listes.py (Python) et apps/_listes.sh (bash) : UN lecteur pour les six programmes (app-log-check, app-log-live, nginx-hardening, nginx-log-audit,
    sync-crowdsec, web-monitor), qui avaient chacun leur analyseur de apps/team-ips.list.
  - Liste blanche : /etc/default/nginx-tools-white-list.conf, lue SEULEMENT là (jamais dans ~ : elle donne accès aux sites DEV et LAB). Lieux :
    /etc/default/nginx-tools-ip-location.conf puis ~/.nginx-tools-ip-location.cfg (descriptif : aucun accès ; la plage la plus précise gagne).
  - Syntaxe commune : « ADRESSE-OU-PLAGE  # libellé  [option] [option] » ; options [partagée] (plusieurs personnes : on affiche le lieu, jamais une personne) et
    [protégée] (jamais bannie ni recommandée au bannissement, sans accès) ; casse et accents indifférents ; IPv4 et IPv6 ; option inconnue ou adresse invalide
    signalées avec fichier:ligne, sans jamais arrêter le programme.
  - Transition : tant que le nouveau fichier n'existe pas, l'ancienne liste apps/team-ips.list est lue, avec « ANCIEN emplacement, à migrer ». Variables
    d'environnement NGINX_TOOLS_WHITE_LIST et NGINX_TOOLS_IP_LOCATION (fichier unique, sans repli) pour les tests.
  - Fonctions bash : listes_blanche, listes_lieux, listes_valides, listes_ne_pas_bannir (liste blanche + lieux [protégée]), listes_resume (la ligne « Listes : … »).

Bugs corrigés :
  - Défaut trouvé par un test avant livraison : listes_lire séparait les champs par une tabulation ; « read » avec une tabulation fusionne les champs vides, donc une
    entrée sans options décalait les champs (« ligne  : pas-une-adresse », numéro perdu). Séparateur : le caractère 037 (jamais un blanc).

Garde-fous et cas limites traités :
  - Fichier absent ou illisible : liste vide ; deux fichiers de lieux : les deux comptent ; une adresse invalide n'est jamais écrite dans nginx ni comptée.

Vérifications effectuées :
  - 9 tests (test_listes.py) : syntaxe, options, priorités, plage la plus précise, ~ pour les lieux seulement, repli transitoire, CLI ; lecteur bash identique au lecteur Python ;
    champs vides conservés ; ShellCheck 0.11.0 et ruff 0.16.9 sans signalement.

Action requise de ma part (ou « aucune ») :
  Aucune (nginx-hardening.sh --update crée ou migre les fichiers).
