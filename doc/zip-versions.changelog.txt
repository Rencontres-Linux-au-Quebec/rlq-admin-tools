## 1.7.20261010.215000 — Bilingual display (French / English) and configuration file

Reason for the request:
  « All the other programs should be bilingual. In the programs' configuration files, some options should be defined too, including the language. »

Changes:
  - Display in French (language of the code, nothing changes) or English: --lang en|fr, variable ZIP_VERSIONS_LANG, key LANGUAGE of the configuration file (auto = follow the environment), NGINX_TOOLS_LANG (language imposed on all tools), then LC_ALL / LC_MESSAGES / LANG.
  - Catalog lang/zip-versions.en.po (75 entries, standard PO format: Poedit, Weblate, Crowdin...); adding a language = adding lang/zip-versions.XX.po, without touching the code.
  - Configuration file: /etc/default/zip-versions.conf THEN ~/.zip-versions.cfg (the last one wins), -c/--config FILE for that file ALONE, command line takes priority. Keys: INSTALLED, LANGUAGE, NGINX_DIR.
  - At start, two lines: « Configuration read: ... » (exactly which file(s)) and « Options: ... » (summary of the important options).
  - Documented example: doc/zip-versions.conf.example.

Bugs fixed:
  None.

Safeguards and edge cases:
  - A message without translation stays in the source language (never an error); a half-translated line is rendered intact; unknown language: English (unknown locale) or French (no variable).
  - Invalid value in the configuration file (integer or yes/no expected): reported by « WARNING: configuration value ignored », never fatal; the file is read, never executed.
  - Programs that parse another program's output impose French on it (NGINX_TOOLS_LANG=fr): parsing does not depend on the display language.

Checks performed:
  - test_i18n.py (language choice, PO reading, complete catalog of each program, no translation containing French, identical help by --lang en and by LANGUAGE=en of the configuration file); the program's test module; ruff, ShellCheck; full suite under mawk and gawk.

## 1.0.20261001.092458 — Initial version: versions contained in the archives

Reason for the request:
  Before attaching the archives to a discussion, know which is the latest version of each program and of the
  configuration contained in each .zip — and therefore which archive to send (2.35 had been sent instead of 2.36).

Changes:
  - New program zip-versions.py. Reads the archives WITHOUT extracting them (zipfile): type (nginx-tools, tests,
    nginx-odoo-config, from the top-level directory), most recent file, version of each program
    (__version__ or SCRIPT_VERSION of the .sh and .py, apps/ and tests/run-all.sh included), and for the nginx configuration the
    last date of the README.md log and the number of files.
  - Arguments: .zip archives or directories (their .zip; a directory containing an installation is also examined);
    default: current directory.
  - Several archives of the same type (e.g. « nginx-tools (2).zip »): the most recent is designated (highest version, then
    configuration log, then date of the most recent file); for the others, the older programs.
  - Final section « ARCHIVES TO ATTACH TO THE DISCUSSION »: the most recent archive of each type, with its path;
    missing nginx-tools or tests reported.
  - Option --installed [FOLDER]: compares the selected archives with the installation (default /root/scripts) — « to deploy »,
    « outdated archive, do not send it » or [OK] — and the nginx configuration with the content of --nginx-dir (default /etc/nginx):
    identical, different, missing files (fail2ban/ excluded: copied elsewhere by nginx-hardening.sh).
  - Usual options: --changelog, --report-err, --version; help in alphabetical order.
  - Exit code: 0 without warning, 1 otherwise (unreadable archive, source not found, difference with the installation).

Bugs fixed:
  None (first version).

Safeguards and edge cases:
  - No extraction or write; members over 4 MB and __pycache__ ignored; corrupted archive reported without stopping.
  - The tested copy of the configuration (tests/nginx-odoo/) is not counted among the programs of tests.zip.
  - Same archive given twice: examined only once. Python 3.8; no configuration (nothing to set).

Checks performed:
  - Tests (test_zip_versions.py): versions read in the three archive types, most recent archive designated,
    corrupted archive, comparison with an installation (to deploy, outdated, identical), different configuration.
  - Conventions (version, changelog, sorted help, --report-err, Ctrl-C, Python 3.8). Full suite.

Action required from me (or « none »):
  Before sending the archives: « zip-versions.py ~/Downloads » (or the folder where they are), attach those of the
  « ARCHIVES TO ATTACH » section. On a server: « zip-versions.py --installed » to see what is left to deploy.
