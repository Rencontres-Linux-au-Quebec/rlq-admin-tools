## 1.3.20261015.143436 — Filtre d'anonymisation de la sortie

Motif de la demande :
  « [1] Il faudrait avoir une nouvelle option afin d'anonymiser les données affichées par chacun des programmes » (choix : pseudonymes stables ; IP, courriels et identifiants Odoo, jetons dans les URL/journaux ; tous les programmes)

Détail des modifications :
  - main : deux modes — « PROGRAMME VARIABLE -- COMMANDE » (bash : traduction et/ou anonymisation) et « --anonymiser-seul -- COMMANDE » (Python). lancer(…, anonymiser) pose NGINX_TOOLS_ANON_ACTIF chez la commande.

  - ANONYMIZE du fichier de configuration : seulement si la sortie est un terminal (un tube ou cron ne reçoit jamais un texte modifié d'après la configuration seule ; --anonymize ou NGINX_TOOLS_ANONYMIZE=1 le force).

## 1.1.20261011.093635 — Ctrl+C fonctionne derrière le traducteur

Motif de la demande :
  « Pour les tests, on ne peut les arrêter avec Ctrl+C. »

Détail des modifications :
  - Le traducteur remplace signal.signal(SIGINT, SIG_IGN) par un gestionnaire vide.

Bugs corrigés :
  - Symptôme : en anglais, run-all.sh (et tout programme bash traduit) ne réagissait plus à Ctrl+C. Diagnostic : SIG_IGN est hérité à l'exec : la commande, Python et les tests ignoraient tous SIGINT. Un gestionnaire, lui, revient au comportement par défaut à l'exec.

Garde-fous et cas limites traités :
  - Le traducteur lui-même ne s'arrête pas sur Ctrl+C : il attend la fin de la commande et rend son code de retour. Un programme qui gère Ctrl+C lui-même (invites, tableaux de bord) garde son comportement.

Vérifications effectuées :
  - run-all.sh lancé en français puis en anglais, interrompu par SIGINT envoyé au groupe de processus pendant la passe des tests : arrêt immédiat, code 130.

Action requise de ma part :
  aucune (remplacer apps/_traduire.py).

## 1.0.20261010.220000 — Création : traduction de la sortie des programmes bash

Motif de la demande :
  « Il faudrait que tous les autres programmes soient bilingues. »

Détail des modifications :
  - Lance un programme bash derrière le traducteur (catalogue lang/PROGRAMME.XX.po) : sortie et erreurs traduites ligne par ligne ; invite sans fin de ligne (« Continuer ? [o/N] ») traduite après 50 ms de silence ; pseudo-terminal de même taille quand la sortie est un terminal (couleurs, largeur), tube sinon ; stdout et stderr confondus (2>&1) dans un seul tube pour garder l'ordre ; entrée standard intacte ; code de retour conservé.
  - En français : exec direct (aucun processus de plus, sortie inchangée).
  - AUTRES_CATALOGUES : catalogue d'un autre programme dont la sortie est affichée telle quelle (nginx-log-audit.sh -> sync-crowdsec-blocklist).

Bugs corrigés :
  Aucun.

Garde-fous et cas limites traités :
  - NGINX_TOOLS_I18N=1 empêche de relancer deux fois ; Ctrl-C va aussi au programme (même groupe) ; SIGPIPE normal (| head) ; processus fils gardant la sortie ouverte : on n'attend pas.

Vérifications effectuées :
  - test_i18n.py (MecanismeTraduire : français inchangé, anglais, invite, code de retour, 2>&1, NGINX_TOOLS_LANG).
