## 1.0.20261007.175936 — First version: list of unsent e-mails and offer to resend them

Reason for the request:
  « A program that lists the unsent e-mails and then offers to resend them; show me the title of the unsent e-mails. »
  (following the failure to send registration e-mails: SMTP errors 452, 503 and 550 found by app-log-check.py)

Changes:
  - odoo-mail-retry.py: list of e-mails in « Delivery Failed » (state « exception » of mail.mail) of the last --days days (30 by default): for EACH e-mail its number,
    date (local time), TITLE, recipients (masked: j***@example.org; --details to see them) and the cause of the failure recognized from Odoo's error
    (diagnostics base of app-log-check.py), « transient » or « PERMANENT »; then the totals per title, per cause and per day; pending and sent e-mails.
  - Resend menu on a terminal: [t] all, [l] a batch of the oldest (--batch N, 10 by default), [c] one by one, [N] none. Resend = put the e-mail back in the
    « Outgoing » state like Odoo's « Retry » button; the scheduled action « Mail: Email Queue Manager » sends it at its next run. Each resend is recorded in
    /var/lib/nginx-tools/mail-retry.log (date, database, count, numbers).
  - Without a terminal: list only; --resend --yes resends without a question (--batch N: only the N oldest); --no-prompt: list only even on a terminal.
  - apps/_odoo_db.py 1.3: bases_odoo(), courriels_en_echec(), remettre_en_attente() (the ONLY write); app-log-check.py 2.13: « permanent » flag of the diagnostics.
  - Configuration (common rule): /etc/default/odoo-mail-retry.conf THEN ~/.odoo-mail-retry.cfg (the last one wins; keys DAYS and BATCH); -c/--config: that file ALONE; the command
    line takes priority; « Configuration read: ... (the last one wins) » and an « Options: ... » line displayed at every run.
  - Options (alphabetical order): --batch, --changelog, -c/--config, --days, --db, --details, --no-prompt, --report-err, --resend, --verbose, --version, --yes.

Bugs fixed:
  - (apps/_odoo_db.py, previous delivery) courriels() read the subject from mail_mail.subject: this column does not exist, mail.mail inherits from mail.message (_inherits) and the subject
    is in mail_message. On a real database the query failed and the « Failing subjects » line of app-log-check.py stayed empty without a message; the test simulator could not
    see it. Fixed by a join on mail_message.

Safeguards and edge cases:
  - Read-only for the list (transaction forced read-only by PostgreSQL); the write only touches the state and modification date of e-mails STILL in failure
    (AND state = 'exception'): an e-mail already resent or deleted is reported « ignored », never modified; numbers validated as integers.
  - No resend without a terminal without --resend --yes; several databases: --db required for a resend without a question.
  - Warning before the resend: PERMANENT cause (sender refused, authentication, relay: it will fail again); mail.session.batch.size undefined or above 20
    with more than 10 e-mails (risk of hitting the messages-per-connection limit 452 again: resend in batches).
  - PostgreSQL unreachable, unknown database, component missing: clear message, code 2; invalid configuration file: line reported and ignored.
  - The program itself sends nothing: Odoo sends (scheduled action), with its own outgoing server.

Checks performed:
  - Tests in test_odoo_mail_retry.py (list, titles, masking, causes, menus t / l / c / none, --resend --yes, --batch, warnings, resend log, read-only and
    guarded write, configuration, several databases); ruff 0.16.9; run under Python 3.8 (syntax).

Action required from me (or « none »):
  None for the list. Before resending: fix the PERMANENT cause (see app-log-check.py [5]) and set mail.session.batch.size if there are many e-mails.
