## 1.3.20261015.105354 — Automatic creation of the robot's API key and writing it in the configuration

Reason for the request:
  « On the first run, create the API key (with a one-year expiry?) and fill in all the configuration files that need it. »

Changes:
  - --create-bot now also creates the robot's API key: random temporary password set by the administrator, web session like a browser (class WebSession: login, identity check, key wizard), key requested for 365 days, then 180, 90, 30, 7 if Odoo refuses (maximum duration of non-administrator accounts); the password is then replaced by another random password that is thrown away (web login impossible). Functions generate_api_key, make_bot.
  - The key is never displayed: it is written with LOGIN in /etc/default/odoo-chat-post.conf (or NGINX_TOOLS_ETC_DEFAULT; --bot-config FILE, repeatable) with mode 600; the old version of the file is saved (.YYYYMMDD-HHMMSS.bak, 600); the robot is added to MEMBERS if it exists; a comment notes the creation and expiry dates. Functions write_key_config, check_writable.
  - --renew-key: new key for an existing robot (the old one stays valid until it expires). Without it, an existing robot is not touched.
  - The administrator gives HIS key through ODOO_API_KEY and --login ADMIN: it is written nowhere. The other programs (app-health-check, web-monitor, app-log-live) do not need the key: when they send alerts, they will call odoo-chat-post.py --post, which reads this single file (one place to protect and renew).
  - Files: odoo-chat-post.py, doc/odoo-chat-post.conf.example, doc/odoo-chat-post.changelog.txt, lang/odoo-chat-post.en.po.

Bugs fixed:
  - None.

Safeguards and edge cases:
  - The files to write are checked BEFORE any creation: if not writable (not root), nothing is created (a key that is not recorded would be lost).
  - Odoo refusal (two-factor authentication, different version, web session impossible): warning, the password is still made unusable (finally block), configuration untouched, manual steps displayed.
  - --login equal to the robot: refused (use the administrator account). --dry-run writes nothing.
  - NOT TESTED on a real Odoo: Odoo does not allow creating a key through the external API; the route used (web session, res.users.identitycheck, res.users.apikeys.description.make_key) imitates the browser and may differ by version (18.0) or be blocked by two-factor authentication; the tests use a fake server. Try --create-bot --dry-run first.

Checks performed:
  - test_odoo_chat_post: 31 tests including 6 new ones (key written with mode 600 with backup and MEMBERS, duration reduced to 90 days, web session refused, non-writable file, --renew-key, administrator --login), test_i18n, test_conventions, test_config_defaut.

Action required from me:
  - As root: ODOO_API_KEY=<administrator key> odoo-chat-post.py --login ADMIN --create-bot --dry-run, then without --dry-run; check with --list; if Odoo refuses, follow the manual steps displayed. Note the expiry date (renew with --renew-key).

## 1.0.20261015.085700 — First version: alert channels and threads in Odoo (Discuss)

Reason for the request:
  « [1] Alerts should be sent to Odoo discussion channels to centralize the problems and warn the team (who have no access to the Linux console). Create these discussion channels and write a first message giving the reason for each: Odoo-Erreurs (HTTP 4xx, HTTP 5xx, Linux, Postgres, NGINX, BBB, Autres), Odoo Stats (Sommaire, Pages les plus visitées), Évent-Inscriptons (JPOL26-Inscriptions, JPOL26-Sondages) [2] if you have other recommendations, do not hesitate: the goal is to keep everybody informed of the important things while organizing events. Which other discussion channels do you suggest? »

Changes:
  - --create [--dry-run] [--suggested] [--event NAME]: creates in Odoo (XML-RPC, API key) the channels and threads (Odoo 18 sub-channels, field parent_channel_id) of the catalog doc/odoo-chat-post.catalogue.json, with a first message (reason, source, local date); the accounts of the group (--group, default base.group_user) become members of the channels (--no-members to avoid it).
  - --post CHANNEL/THREAD --message TEXT (« - »: standard input): posts an alert in a thread; --list: state of each channel and thread.
  - Catalog: Odoo-Erreurs (HTTP 4xx, HTTP 5xx, Linux, Postgres, NGINX, BBB, Autres), Odoo-Stats (Sommaire, Pages les plus visitées), Évent-Inscriptions (EVENT-Inscriptions, EVENT-Sondages); suggested channels (--suggested): Odoo-Sécurité, Odoo-Courriels, Odoo-Sauvegardes, Odoo-Mises-à-jour, Évent-Jour-J.

Bugs fixed:
  - None.

Safeguards and edge cases:
  - An existing channel or thread is never modified or repeated (no second first message); --dry-run writes nothing.
  - The API key is never displayed or passed on the command line; warning if the file that holds it is readable by other accounts.
  - Odoo without sub-channels: each thread becomes a « Channel — Thread » channel. Unknown group, authentication refused, empty message, thread not found: clear message, non-zero exit code.
  - Not tested on a real Odoo: the tests use a fake XML-RPC server; check first with --create --dry-run then --list.
