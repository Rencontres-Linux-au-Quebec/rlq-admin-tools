## 1.0.20261015.185024 — Creation: documentation published to the document_page wiki (OCA) or the website pages

Reason for the request:
  « An option to specify whether the documentation is written in a web page or in a wiki like the OCA document_page module (already installed). Run a validation to make sure the module is really installed and working before creating the wiki pages. »

Changes:
  - New program odoo-docs.py: reads docs/en and docs/fr (docs/build_docs.py: Markdown -> HTML, real --help inserted) and writes them into Odoo through the external API (XML-RPC, API key).
  - --target wiki: root category (--root, default nginx-tools) -> English / Français categories -> one page per document (type content). --target website: pages /docs/<lang>/<page> (ir.ui.view qweb + website.page).
  - --check: validation only. --dry-run: shows without writing (no write test). Configuration file: /etc/default/odoo-docs.conf then ~/.odoo-docs.cfg (keys API_KEY, DB, DOCS_DIR, LANGUAGE, LOGIN, ROOT, TARGET, URL).
  - Wiki validation BEFORE writing: module document_page present and in state installed (version displayed); models document.page and document.page.history; fields name, type, parent_id, content (content not read-only); create / write / unlink rights of the account; then a REAL test: creation of a temporary category and page, edit, read back, history count, deletion (even on failure).
  - Idempotent updates: a page is looked up by name and parent; the content is rewritten only if it differs (« unchanged » otherwise); revision summary « odoo-docs.py <version> » (wiki history).
  - Files: odoo-docs.py, doc/odoo-docs.changelog.txt, doc/odoo-docs.conf.example, lang/odoo-docs.en.po, docs/{en,fr}/17-odoo-docs.md.

Bugs fixed:
  - None.

Safeguards and edge cases:
  - Module missing, not installed, model or field missing, right missing, read-only content: refusal BEFORE any write, with the remedy.
  - API key: ODOO_API_KEY variable or configuration file; warning if the file is readable by other accounts; never displayed. Missing settings: exact list of the missing keys.
  - No --target nor --check: refusal with an explanation.

Checks performed:
  - test_odoo_docs: 10 tests against a FAKE Odoo (modules, rights, fields, wiki, history, website): validation, refusal, idempotence, simulation, website target.
  - NOT TESTED on a real Odoo: the document_page field names (OCA, 18.0) are deduced from the documentation; the validation checks them at run time (fields_get + real test), so a mismatch will be reported clearly.

Action required from me:
  - Create the publishing account's API key, write /etc/default/odoo-docs.conf (template: doc/odoo-docs.conf.example), then: odoo-docs.py --check --target wiki, odoo-docs.py --target wiki --dry-run, then without --dry-run.
