## 1.1.20261021.235747 — Steps of the test (N key): steps.txt

Reason:
  The N key of app-log-live.py marks the start and the end of each action of a test; the archive must hold them, with their times, to match the log lines.

Changes:
  - Recorder.step_start(description) / step_end(reason): step numbers, times, descriptions; the open step is closed before a new one starts.
  - records.log and stream-all.log: "STEP n START hh:mm:ss — description" and "STEP n END hh:mm:ss — duration s — description".
  - steps.txt (new, bilingual header) in the archive, and "Steps" line in README.txt.
  - stop(): a step still open is closed with reason "recording stopped".

Bugs fixed:
  none.

Safeguards and edge cases:
  - step_start returns None when no recording runs or when it is stopping (no crash, nothing written).
  - Description masked with the same mask() as the lines; spaces collapsed; 200 characters maximum.

Checks:
  - test_record.py: test_etapes_debut_fin_dans_records_log_et_steps_txt.

Action required:
  none.

## 1.0.20261020.230008 — Creation: recording of a test for app-log-live.py (R key, --record-test-log)

Reason:
  Companion of the R key and of --record-test-log of app-log-live.py: gather, over a window of time, what is needed to analyze a test of the site, in one .tar.xz.

Changes:
  - Recorder: start() (work folder 0700, size of each log file noted), add(line, category) for each stream line, stop() (in the background or wait=True): last samples, raw extracts, journal extract, README.txt, archive.
  - Archive contents: README.txt (French and English), records.log (kept lines), stream-all.log (all lines with their category), raw/ (log files from their size at the start, rotation followed, systemd journal of the service between the two instants), network/ (ss every SAMPLE_S seconds), db/ (pg_stat_activity and ir_cron locks every SAMPLE_S seconds; start and end snapshots: counters, dates, identifiers and states of the Odoo tables; table columns), context/ (systemctl show, Odoo configuration with whitelisted keys only, modules of interest, program versions).
  - default_folder(): APP_LOG_LIVE_RECORD_DIR, under sudo ~SUDO_USER/app-log-live-records, else LOG_DIR/records, else ~/.local/state/app-log-live/records.
  - Limits: 30 minutes by default (set by app-log-live.py), 200 MB of lines, 50 MB per raw file, 500 MB free disk needed.

Bugs fixed:
  none (new component).

Safeguards and edge cases:
  - Masking (mask): tokens first (survey paths and tokens, hash/token/key/sig/secret parameters, UUIDs, hexadecimal strings of 20 characters or more), then the Anonymiseur of app-log-live.py (addresses, e-mails, names), then SQL literals replaced by '?'. Without the Anonymiseur, FallbackMask (random salt, this archive only).
  - A masking exception drops the line; it never writes the real value.
  - Log rotation during the recording: the end of the old file (name.1, same inode) then the new file whole.
  - A symbolic link as folder is refused. The archive is written as .part, its mode is 0600, its owner is the person who ran sudo.
  - Sources that fail are noted in README.txt (log file missing or unreadable, PostgreSQL unreachable, ss absent, journal unavailable): never a crash.
  - Snapshots only read: queries go through the read-only function of apps/_odoo_db.py.

Checks:
  - Smoke test with fake sources (see the changelog of app-log-live.py 1.93).

Action required:
  none.
