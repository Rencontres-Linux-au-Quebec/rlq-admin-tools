## 2.38.20261016.173838 — Ctrl+C works while the program is running (timeout --foreground)

Reason:
  « Le Ctrl+C ne fonctionne pas lorsque le programme est en cours nginx-log-audit.sh v2.37 (lorsqu'appelé par app-log-live.py) »

Changes:
  - Every « timeout N COMMAND » is now « timeout --foreground N COMMAND » (12 places: journalctl -g over 100 days, host, dig, getent, whois).
  - Header: « Copyright (C) 2026  Services-Conseils Linux » (was: Rencontres Linux Québec <info@rencontres-linux.quebec>).

Bugs fixed:
  - Symptom: Ctrl+C without effect while the program runs (--evidence, --ban, --investigate), up to 60 s per command, several commands in a row.
    Diagnosis: without --foreground, timeout runs the command in ANOTHER process group: the terminal's Ctrl+C never reaches it, and bash runs
    the INT trap (the confirmation) only when the foreground command (timeout) ends. Reproduced in a pseudo-terminal. Fix: --foreground.

Safeguards and edge cases:
  none.

Checks:
  - test_ctrl_c: test_bash_ctrl_c_pendant_timeout_foreground_question_immediate, test_aucun_timeout_sans_foreground_dans_les_programmes_bash.

Action required:
  none.

## 1.2.20260918.195720 — EDT, colonne %, description codes HTTP, IP publique, OS, dernière exécution

Motif de la demande :
  Plusieurs demandes groupées : horodatage de version en EDT (pas UTC), affichage correct des accents, colonne %
  dans --stats, description de chaque code HTTP dans la répartition, IP publique et système d'exploitation dans
  l'en-tête, date de la dernière exécution affichée.

Détail des modifications :
  - VERSION recalculée avec l'heure EDT réelle (America/New_York) plutôt que UTC.
  - Locale forcée à C.UTF-8 par défaut (seulement si LC_ALL n'est pas déjà défini) — protège l'affichage des
    accents sous cron/services minimaux sans écraser un réglage existant.
  - --stats : nouvelle fonction with_pct() ajoute une colonne pourcentage à chaque liste (statuts, chemins
    bloqués relatif au total bloqué, top chemins/IP/UA relatif au total général).
  - Nouveau tableau associatif HTTP_DESC : description française courte pour les codes HTTP les plus fréquents
    (200, 301-304, 400-405, 429, 444, 499, 500-504), affichée dans la répartition par statut.
  - En-tête du rapport : ajout de l'IP publique (curl vers icanhazip.com, délai 3s, validée par motif IPv4/IPv6
    avant affichage) et du système d'exploitation (/etc/os-release, repli sur uname -sr).
  - Date de la dernière exécution mémorisée par environnement (STATE_DIR/<env>-lastrun) et affichée juste après
    la ligne "(lignes nouvelles depuis la derniere execution seulement)".

Bugs corrigés :
  - VERSION en UTC au lieu d'EDT (erreur de ma part).
  - Collision de nom critique : "readonly VERSION" entrait en conflit avec la variable VERSION que définit
    /etc/os-release lui-même lors du "source" pour lire le nom de l'OS, causant un plantage
    ("readonly variable") à chaque exécution. Renommé en SCRIPT_VERSION partout dans le fichier.
  - IP publique : un curl qui réussit mais reçoit une page d'erreur non vide (portail captif, restriction réseau)
    passait le test "non vide" et affichait du texte non pertinent comme si c'était une IP. Ajout d'une validation
    de forme (regex IPv4/IPv6) avant affichage, sinon message "indisponible" explicite.

Garde-fous et cas limites traités :
  - curl vers icanhazip.com limité à 3 secondes : ne bloque jamais longtemps un serveur sans accès sortant.
  - La locale forcée ne remplace jamais un LC_ALL déjà défini par l'utilisateur ou le système.
  - Un code HTTP absent du tableau HTTP_DESC affiche "(non documente)" plutôt que de faire échouer le script.

Vérifications effectuées :
  - bash -n (syntaxe) sur le script final.
  - Test fonctionnel complet avec logs fictifs : --init --stats (colonnes %, descriptions HTTP visibles), deuxième
    appel incrémental (date de dernière exécution correcte), reproduction ET correction du bug de collision
    readonly VERSION, reproduction ET correction du faux positif d'IP publique (réponse d'erreur réseau du
    bac à sable utilisée comme cas de test réel).

Action requise de ma part (ou « aucune ») :
  Confirmer que icanhazip.com est joignable depuis vos serveurs (sortant HTTPS) ; sinon l'IP publique affichera
  systématiquement "indisponible", ce qui est un comportement correct mais pas très informatif.
