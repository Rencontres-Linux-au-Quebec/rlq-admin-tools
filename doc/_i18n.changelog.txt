## 1.17.20261017.105442 — Language from the environment as gettext; the setting that decided is shown

Reason:
  « [7] Peux-tu t'assurer que tous les programmes lisent les variables d'environnement en Linux qui déterminent la langue, cela n'a pas fonctionné si je change la variable LANG à fr, fr_CA, C, en »

Changes:
  - langue_et_origine(): GNU LANGUAGE (list « fr_CA:fr:en », the first available language) unless the locale is C / POSIX, then LC_ALL, LC_MESSAGES, LANG
    (the first defined wins); returns the origin « LANG=fr_CA.UTF-8 », « LC_ALL=C.UTF-8 ; LANG=fr_CA.UTF-8 ignorée(s) », « LANGUAGE=fr du fichier de
    configuration », « WEB_MONITOR_LANG=fr »…; langue() unchanged for the callers. Contexte.origine_langue; « Options : --lang xx (origine) ».

Bugs fixed:
  - « LANG=fr does not work »: the detection was right for LANG alone (checked: fr, fr_CA, C, en), but a defined LC_ALL or LC_MESSAGES, a LANGUAGE= key of a
    configuration file or NGINX_TOOLS_LANG / PROGRAM_LANG silently wins over LANG (the POSIX order); nothing said which one. Fix: the origin is printed,
    with the variables ignored; GNU LANGUAGE (used by desktops) was not read at all: now read like gettext.

Safeguards and edge cases:
  - --lang on the command line: no origin printed (nothing to explain).

Checks:
  - test_i18n.LangueDeLEnvironnement; tests of the program (Options line compared without the origin: helpers.sans_origine).

  none.
